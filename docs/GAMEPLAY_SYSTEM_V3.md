# 变量玩法 v3

v3 把玩家可理解的行动提示、程序结算的条件与效果、承诺与余波、作者草稿放在同一套玩法定义中。AI 提供故事中的事实变化及叙事，程序负责变量权限、数值限制、规则费用、触发次数和运行记录。

## 生成与兼容

生成入口使用 `gameplay_system_prompt.dart`。默认设计 4–12 个变量，通常突出 3–5 个核心状态，不要求隐藏变量配额。玩法概述需说明行动、收益、代价与替代路径，具体机制由题材决定。

重新生成时向模型提供已有设计作为参考，要求保留含义未变的 key、分组和规则 id。生成结果先进入草稿，应用草稿才修改正式玩法。已有 NPC 关系、任务、物品、线索和剧情事件仍由原有状态系统维护。

旧 schema 1 的非引擎 `rule/computed` 权限仍沿用现有迁移到 schema 2 的逻辑；schema 2 的文字规则不强制转成可执行规则。新生成使用 schema 3。解析器先读取模型，再检查原始结构，避免错误的操作或引用被模型的宽容读取静默丢弃；错误包含对应变量或规则的中文说明。

## 玩家可见信息

变量新增字段：

| 字段 | 含义 |
| --- | --- |
| `playerHint` | 非剧透的行动方向，不包含幕后值、隐藏阈值或秘密 |
| `isCore` | 优先展示的核心状态；其他已知变量可展开 |
| `revealWhen` | 全部满足时显示该变量，格式同规则条件；空数组表示无额外限制 |
| `advanceOnTimeChange` | 可选正数，仅用于 `authority=rule` 的 `clock` |

公开数值显示精确值；模糊数值显示阶段。幕后变量不进入玩家面板，完整定义仍供作者查看。`revealWhen` 根据当前状态判断，并非独立的永久解锁记录；适合使用持续成立的章节标记或单向进度条件。

公开结构化规则须提供 `playerSummary`，用于说明玩家能观察到的后果。`when/effect` 是作者与叙事上下文的完整解释。自然语言提示和摘要仍需要作者检查，结构校验不能判断所有间接剧透。

## 条件和执行

规则保留 `id/title/when/effect/visibility`，新增：

| 字段 | 执行意义 |
| --- | --- |
| `conditions` | 非空数组，全部满足才可触发 |
| `costs` | 数值费用，先检查余额并原子扣除 |
| `effects` | 对已声明变量执行 `set/inc/append/remove` |
| `threads` | 打开、兑现、违背承诺与余波事项 |
| `once` | 默认 `true`，每份进度只触发一次 |
| `cooldownTurns` | 非负整数；设为 2 时，第 1 轮触发后最早第 3 轮再次触发 |
| `playerSummary` | 玩家能够知道的后果说明 |

条件格式为 `{"path":"调查.戒备","op":"gte","value":60}`。

- `eq/neq` 支持与变量类型匹配的值。
- `gt/gte/lt/lte` 仅比较数值。
- `contains` 检查文本或列表中的文本项。
- `changed` 不需要 value，比较本轮结算条件快照与回合开始的值。

费用格式为 `{"path":"调查.资源","amount":2}`，金额非负，扣除后不能低于零或定义的正数下界。效果格式为 `{"op":"inc","path":"调查.戒备","value":10}`。`inc` 只用于数值，`append/remove` 只用于列表，`set` 的值需符合目标类型、范围与选项。程序效果只可修改 `ai/rule` 变量。

一个有效回合的顺序：

1. 从上一份快照初始化变量与运行记录。
2. 应用合法 AI 补丁，检查权限和 AI 单轮净变化上限。
3. 根据本轮前后时间记录推进配置的时钟，处理有事实依据的台账操作。
4. 固定一份条件判断快照；每条规则的条件都读取这份快照。
5. 按定义顺序检查规则的单次限制、冷却和条件，按最新余额试算费用与效果。
6. 整条规则可执行才提交数值、台账与触发记录，生成玩家与作者各自的变化信息。

同轮不会因前一条规则的效果连锁触发其他规则。费用与效果共享原子提交，任一项无效或越界，整条规则回滚。`maxDelta` 限制 AI 对单个变量的本轮净修改，程序定义的费用、效果和时间推进按定义结算。

缺失或损坏整个玩法补丁时，本轮保留上一份玩法状态与运行记录，等待补丁修复。合法的空补丁仍可推进有效时间与程序规则。重复处理同一回合 id 不会再次扣费或重复触发。

## 可选时间压力

`advanceOnTimeChange` 必须是正数。程序只在前后时间标签都非空且不同的有效回合推进一次，到达上限后停止增长。不会依据消息数量或地点改变自动扣时间。

此字段提供按叙事时间变化推进的有限能力，没有解析自然语言时间、按小时倍增或辨别时间倒流。剧本应说明哪些行动推进时间；日常陪伴故事可以完全不配置时钟。

## 承诺与余波

台账记录放在 `GameplayRuntimeState.threads`，与普通任务、物品和 NPC 数值分开。操作通过 `[THEATER_PATCH]` 的 `threads` 数组或规则的 `threads` 提交。

```json
{
  "op": "open",
  "id": "protect_visitors",
  "title": "替异乡人隐瞒身份",
  "description": "玩家已答应在清查时保护他们的身份",
  "reason": "本轮玩家明确答应保密",
  "visibility": "public"
}
```

`open` 要求稳定 id 和标题；`resolve/break` 只可操作已存在且未结束的事项。AI 操作必须有本轮事实依据，不能把沉默视为答应、把犹豫判为违约。结束的事项仍保留在台账，不能被同 id 重新打开。最多保留 100 项，规则事件保留最近 80 条。

公开事项可在玩家面板和回合反馈查看；幕后事项只供作者和适当的叙事上下文使用。语言模型仍承担事实识别，程序验证格式、合法转换和重复提交，不自行证明故事中的承诺是否成立。

## 草稿、锁组与迁移

`GameplaySystemDraft.merge(current, generated, lockedGroups)` 构造草稿，返回合并后的 `system`、逐项 `changes` 与 `migrationNotes`，不写入正式进度。

锁组保留旧组变量及所有引用其 key 的旧规则，生成草稿中与锁组冲突的定义不覆盖它们。保留规则或揭示条件所依赖的其他变量若被移除、改变类型，合并明确失败并提示同时锁定相应组。旧文字规则没有可靠的结构化引用，锁任意组时一并保留，并显示复核说明。

作者可编辑说明、初始值、范围与规则，通过高级编辑调整完整定义，在本地预演里观察多轮结果。预演不调用叙事模型、不写入正式消息，不验证模型是否能自然表达对应剧情。

应用时：

- 同 key、同类型的变量保留当前值，再按新范围或选项归一化；新增或改类型的变量采用初始值。
- 移除的变量退出当前玩法，已有旧消息快照保留原始记录。
- 同 id 且 `conditions/costs/effects/threads/once/cooldownTurns` 不变的规则保留触发记录；执行机制改变时重新计次。
- 承诺、规则事件、运行轮次和最后回合 id 保留，防止换设计丢失故事历史。

草稿的 `migrateValues` 和 `migrateRuntime` 供正式应用与预演共用。存档与消息快照保存运行状态，以支持恢复和分支继续。

正式应用通过现有存储日志同时提交玩法定义、当前状态和清除提示词缓存后的消息历史。修改已有玩法前自动创建保护存档。新的消息快照同时保存当轮玩法定义和可用的起始基线，回放时按各轮定义结算；从旧消息开分支时使用当时的规则，而不是之后替换的规则。旧档缺少基线时仍沿用原有初始值回放方式。
