# v2.14.0 存档迁移说明

## 范围

应用版本为 `2.14.0+2140`，导出格式升级至 schema 3。旧 schema 1／2 存档仍可加载，缺少的新字段使用默认值，不启动全历史模型分析，也不额外请求模型整理旧记录。

`StoryContinuityState` 以世界／分支角色 ID 为键，保存统一事件顺序、来源、事实修订与冲突、人物知情、章节、导演偏好、改写版本和回合前快照。`NpcWorldState` 保存本世界的关系、印象、羁绊、经历和私聊。角色卡仍提供共享身份与人设。

## 旧 NPC 数据

首次迁移先为已有世界建立旧共享关系基线，再切换到选中世界，避免访问顺序改变起点。基线明确显示升级时的好感；它不证明这些经历在每个世界都发生过。升级后新增世界不继承其他世界的当前关系数值。

能归属单一世界的旧私聊继续可读。多世界绑定或全局绑定产生的混合私聊保存在「旧版私聊归档」，不自动成为任何世界的知情证据。玩家可从原文重新确认重要事实和人物知情范围。来源不明的经历不会通过主线全文、世界书或关系摘要绕回私聊上下文。

## 来源与分支

新主线回合与 NPC 回复批次使用统一顺序，并记录回合前状态。IF 分支按目标回合截断主线、私聊、事实和知情信息；快照不足时要求补齐必要起点关系，未知状态留空。分支继承分支点有效的导演设置。

完整存档、单角色存档、导入保护快照和分支复制都包含连续性数据。导入沿用既有的同 ID 更新规则，保留来源标识；分支复制需要生成新 NPC ID 时，同步重映射知情、事实归属、私聊和改写版本的关联键。来源缺失标记待核对，不伪造依据。HTML 番外持续排除在事实、知情和结算之外。

## 保存与恢复

剧情改写、版本切换、事实纠正、章节关闭及世界状态保存使用存储批处理和恢复日志。批次失败时恢复原值；恢复本身中断时，下次启动继续恢复日志。候选改写在正式采用前仅在内存中预览。

阅读位置单独保存，避免滚动写入覆盖正式剧情状态；导出时仍合并进连续性记录。删除世界同时删除对应连续性和阅读记录。

如需回到 v2.13.1，请使用升级前导出的旧版本备份。旧版本不能完整理解 schema 3 的新增状态；本版不提供原地降级新记录的操作。
